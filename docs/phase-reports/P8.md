## 3. 如何运行、如何打开调试项

```sh
./run.command
```

也可用 Godot 4.7.2 导入 `project.godot`。入夜右侧“成长一夜”中选“守香 · 构筑一夜”或“夺名 · 构筑一夜”启用 P8 编制行为，资源仍来自有限库存、战后选择、夜市和事件；“观祭”可选全 68 个 ID。旧例夜和原 P7 流派夹具保留其历史规则。没有把全部单位塞入一个场景，也没有增加并发上场上限。

点击单位会暂停并打开完整卡片；“专属术式”按实际目标、费用和冷却执行。“标记”只记录目标意图，归客仍须满足已标记精英、直线打击、最长三秒外出和返回合法岗位。榫卯只到外门门扇修门，不清路。铁肩、断刃、白脚没有离开基地权限。

入夜点击“今夜所见”查看图鉴四册简表。首次入场/看见解锁名称和线稿；真实招募、击破、超度或融契推进完整技能与彩色立绘；列名接口可进入第四步。当前例夜科仪由真实入夜解锁，成功结夜后解明。其余科仪与块仅保留 P8 许可的说明/块名，不冒充 P10 玩法。失败记录保留造成终结的击杀或抹名单位 ID；无单位来源的失败不伪造凶手。

调试保持 F1 网格、F2 身高、F3 掩体、F4 镜头框、F6 单位、F9 弹道、F10 FPS。Space 暂停，−/+ 切换 1×/2×。P8 不提供自由移动命令。

```sh
# 全阶段回归；所有历史套件使用 p8-* 前缀，保留旧证据
./tools/test.sh

# P8 全员/行为与原生截图（显式验收初态，不是普通整夜）
./tools/godot.sh tests/P8Suite.tscn -- --capture
./tools/godot.sh --headless --script tests/P8GhostSuite.gd
./tools/godot.sh --headless --script tests/P8PersistenceSuite.gd

# 仅在临时副本中制造缺技能等错误，不改正式源表
python3 tests/test_boot_guard.py --godot /absolute/path/to/Godot --report-prefix p8
```

完整主界面隔离重现：`python3 tools/p8_host_ui_smoke.py --output /tmp/NEW-EMPTY-DIRECTORY`。runner 复制当前源码，仅替换 Night/Codex/Replay 三个 IO 目的地；第一条隔离检查失败立即停止。该按钮流程只覆盖首战，不冒充完整一夜。

图鉴使用 `user://codex.json`；夜程和战斗回放沿用既有存档目录。测试使用隔离的 `/tmp/ye-ci-p8-*` 路径。回放仍绑定本机引擎及规则哈希；新规则不会伪装兼容旧规则的录像。

## 5. 已知缺陷与未完成项

- 全 64 具名画像均按 P8 许可作为高规格静帧占位；**最终精绘终审通过数为 0**。H01–H32、G01–G32 都在最终美术替换/批准清单中，详见 `assets/portraits/p8/manifest.json`。不能把“生成了 64 张”表述为最终精绘已完成。
- 战斗单位采用 8+8 套像素几何骨架、头面与持物、简化步态和实际技能图形，不是最终逐帧角色动画。背景建筑与部分演出继续沿用阶段占位。
- P9 图鉴正式版式、P10 的 12 条科仪和关卡拼装、P11 列名余文、P12 发布验收尚未做。P8 的已实现条件效果不代表对应完整科仪已实现。
- P7 允许延期的 I20 实际效果、F04 融契依然未完成。既有购入接口对本夜阵亡具名人物的复购限制缺口仍单独保留；本阶段验收不使用复购证明夜程通关。
- P8 当前专门验证全员、局部实际行为、两席中途恢复、跨场边界及回放；不把这些控制夹具宣称为两席普通 P8 完整夜程通关或平衡性验收。P7/G1 历史夜程回归另列。
- 旧 P7 自动策略误进入 P8 的那次运行，在守香 n05/n08 出现战败；它不是合格的 P7 回归，也没有证明 P8 普通夜程通关。首场携带差异已单独确认是“夜档无装备对象”与“运行态四个显式空槽”的表示差异，数值和已有装备未丢失；诊断不能抵销实际战败，新技能组合下的整夜策略与平衡仍待验收。
- 测试隔离事故：旧夜程测试曾写入本机图鉴，已保留原档，后续隔离运行验证档案未再变动。缺少事前基线，无法判断哪些记录来自测试。[事故简要记录](p8-codex-io-incident.json)
