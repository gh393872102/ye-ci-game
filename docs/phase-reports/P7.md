## 3. 如何运行、如何打开调试项

双击 `run.command`，或在Godot打开 `project.godot`。入夜选择成长守香夜/成长夺名夜进入普通有限库存夜程；选择流派试炼进入六条固定验收路径；选择观祭后可勾选今夜成长装备预设。原历史例夜入口仍在。

```sh
./run.command
./tools/test.sh
./tools/godot.sh tests/P7Suite.tscn -- --capture --event-frames
./tools/godot.sh tests/P7NightSuite.tscn -- --capture
./tools/godot.sh --script tools/p7_ui_smoke.gd
./tools/godot.sh --script tools/p7_observer_ui_smoke.gd
python3 tests/test_boot_guard.py --godot /absolute/path/to/Godot --report-prefix p7
```

Space暂停/继续，−/+为1×/2×，点击单位暂停并显示完整卡。守香E保留升级预览，通过「装备与构筑」装入真实库存，R点册，F修门；守香没有变异主按钮。夺名E打开变异，T增潮，构筑页按配方融契。装备、技艺和名帖即时显示槽位；暂停装卸不会清空物品使用次数或冷却。点职使用已获得凭据；借神按钮明确列出12香火+1名分和失败风险。旁观、复盘在UI和Session两层保持只读，对祭只控制所选一席。

F1/F2/F3/F4/F6/F9/F10保留网格、身高、掩体、镜头、单位、弹道和FPS；受管夜程/观祭禁用重置战局的调试入口。默认镜头仍是120身位全图的约20%切片；不会把镜头切近来掩盖路径、站位或反馈。

手工验收：先在成长守香夜装入初始I17/Y01，查看库存扣减和四槽；推进战后奖励/夜市/事件，下一场检查携带。再打开六条试炼按屏内步骤装备、点册/融契/借神，观察表中反馈。最后在观祭启用模板并分别旁观、对祭，保存记录后通过本机种子检索复盘，验证只读卡和终态一致。

### 本阶段资源曲线调整

G1初始实战连续失败，证据保留于 `p7-g1-initial-failure-results.json`，0.18/12曲线下进一步定位无效自动施法的预算证据见 `p7-resource-tuning-evidence.json`。旧P6通关样本曾选择两次香火回复牌与两次维修牌；成长夜替换这些原型牌后，新装备与自动技能仍消耗香火，却没有等量经济供给。策略复核已实际尝试点职、装备、合法补员、优先点册精英与保护名册，不以胜负断言放宽或临时改HP补救。

有效目标检查与维修工人选择修复后，0.18曲线下头目战仍在340.95秒失败，距天亮19.05秒，末香1.171；13次维修共68.4香、4次点册16香且3次完成返9香，其余支出为实际建障/扛门。没有放宽胜负断言或临时加血。回复继续调到0.24/秒，比原0.12增加的0.12相当于旧例夜两张回复牌的总加成，头目战最多多43.2香。第一次0.24实战仍失败但剩9.48香，进一步查明验收策略漏掉名册房门，且300缺损阈值会使300耐久门永远等不到维修。该结果不能只归因于收入不足；最终验收改为按真实门耐久选择维修时机，未再上调资源。
