## 从哪里开始

能运行桌面工程时，请安装 Godot 4.7.2 stable，检出这次评审的标签，在编辑器导入根目录的 `project.godot` 后按 F5 从正式标题进入。macOS 也可运行以下命令。请从标题开始，使用新存档或独立系统用户。

```sh
git clone --branch p11-review-2026-11-18 --single-branch https://github.com/gh393872102/ye-ci-game.git
cd ye-ci-game
./run.command
```

1. 从标题选「开始 → 例夜 → 守香」，进入路线第一场。试一次暂停、购入并部署到合法掩体，再尝试找一个能点册的位置。记录第一次需要猜测的按钮、目标或失败原因。再开夺名例夜，看教学能否解释从潮源入场的差异。
2. 对照阶段报告分别核验复典、放野和自册。特别看晚付出的代价能否在**选择之前**看懂、在**选择之后**从战斗状态中确认。判断三条结尾是否各自回应了玩家此前做过的事。
3. 用同一播放音量试听祭夜和禁声夜的锣、钟、哭。看默认远镜头里的点册、青灯、符印、香烟、弩矢，再按报告的前后帧核对破门与上楼。请指出最难分辨的一对声音或画面，以及会误导什么决策。
4. 看实测表中的 40、80、150 单位三档，分别评价可读性、暂停响应及实时时间。剧情跳转夹具、短窗压力场、历史阶段报告和完整人工游玩请各自标明。只能打开 GitHub 时，可直接阅读报告、查看原生截图、试听 WAV，并把操作手感留为待实玩项。

## 希望收到的评审结果

请先给出「可进入 P12」「有条件进入」或「退回 P11」的判断。按 K1–K8 给出通过、部分通过或证据不足。对每个影响决定的问题，写明席位、场景或种子、实际观感、期望表现、证据链接，以及最小可验收的修改。区分你亲自运行的结果、从截图或音频观察的结果、从源码推断的结果。

美术请重点看祠内空间、人物轮廓、纸墨与木石材质、色彩层次、字号和视线落点。可以批评占位美术对当前阅读的实际影响。64 张人物与鬼物画像仍待最终美术批准。Windows 发布包、手柄整夜和商店交付归后续验收。请把最影响玩家判断的三项排在最前。
