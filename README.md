# 夜祠 · P11 叙事、音频与打磨

这一版加入复典、放野、自册三种结局倾向、五步例夜教学，以及随战斗状态触发的音效与远镜头特效。设计评审从 [给 Grok 的评审说明](docs/GROK-REVIEW-P11.md) 开始，逐项证据见 [P11 阶段报告](docs/phase-reports/P11.md)。

进入「开始守夜」可选手搓编制例夜、经典例夜或按种子拼装的凶夜。十二条科仪进入战斗，三座头目舞台和三项可叠加的无册夜修饰可从观祭编排。按本轮确认，以键鼠为操作验收范围。逐条规则、12 块设计、十个种子的实际地图与三图计时见 [P10 / G2 阶段报告](docs/phase-reports/P10.md)。

## 启动和存档

实测引擎 **Godot 4.7.2.stable.official.ed1daf0bf**，GDScript / Compatibility 2D，无新增运行依赖。双击 `run.command`，或导入 `project.godot` 后运行。Boot 校验原 CSV、技能/特性引用及 P3–P8 配置，包含每个 P8 行为脚本与方法，失败时拒绝开始游戏。

```sh
./run.command
# 换机指定已安装引擎
GODOT_BIN="/absolute/path/to/Godot" ./run.command
```

启动脚本依次检查 `GODOT_BIN`、标准应用目录、相邻 `zhizhacun/.runtime/Godot`、PATH。相邻工程只复用引擎可执行文件，不读取或修改其游戏内容。

入夜可选择成长守香夜、成长夺名夜、观祭、流派试炼；原守香/夺名例夜保留为历史规则入口。成长夜从有限的真实库存开始，三选一、夜市与事件继续产出物品、编制和点职凭据。例夜固定科仪为「例夜安香」，每条路线经过十个节点；中段可选稳妥休整或风险战斗。战后必须选择一张卡才可前进。夜市使用同一份香火，事件会明确列出代价，普通休整不复活陨落者。例夜失败后允许一次免费复香重试当前战斗，恢复范围会在界面列明。

「保存」或「保存并回入夜」会保存当前节点。入夜选择继续时，战斗恢复到原有位置、生命、读条、维修、队列和时钟，并保持暂停，按 Space 继续。保存位置为 Godot 的 `user://night_save.json`（项目自定义用户目录 `ye-ci`，以引擎 `OS.get_user_data_dir()` 实际路径为准）。新夜替换当前夜存档；不提供多槽管理。奖励牌、库存和随机数状态随档保存，读档不会重抽三选一。凶夜使用种子决定补给节点次序、各场祠场组合、头目和默认科仪，也可在标题指定科仪。凶夜开场少四点香火，例夜保留一次免费复香。

设计 1920×1080，默认窗口 1280×720，`canvas_items + keep`。战场仍为 9600 px / 120 身位，默认镜头 `[6080,8000]`、zoom=1，P8 普通人鬼高 80 px，大形 G17–G24/G31/G32 高128–176 px；小地图镜头框为全图的 20%。历史阶段测试保留当时的单位形高配置。

## 战斗操作

两席继续使用同一个 `Combat.tscn`、`CombatSimulation` 和伤害公式。守香初始为晚、铁肩、朱砂与两名杂兵组成的值夜班；夺名从十六只白衣开始。幸存编制、实际生命、升级、已装备香器与变异形态跨节点保留，不重新赠送初始班底。

- Space 暂停/继续；`-` 或小键盘 `/` 为 1×，`=` / `+` 为 2×。打开决策面板或点击单位自动暂停；关闭面板后用 Space 继续。
- Q 购入，选择卡片后只允许部署到高亮掩体岗位，右键取消并退回预留香火。外门外、庭院中央与不匹配职分的岗位会被拒绝。
- 点击单位查看信息；守香 E 保留升级预览，点击「装备与构筑」装卸实际库存的香器、两条技艺和名帖；R 由守香司施术者对合法目标点册，F 选择受损门并派维修者真实行走施工。
- P8 成长夜与观祭可在完整卡中打开「专属术式」，按实际费用、目标与冷却施放；标记精英后归客才可猎步，外门/院心最多3秒并返回掩体。榫卯只到门扇施工；白脚飞瓦限基地内。图鉴四册从入夜页打开，只读展示真实遭遇、招募、击破、超度及失败来源。
- 成长夺名夜点击合法来源单位后 E 选择提灯、上梁或破门，费用为8/12/15香火；融契20香火，按固定配方进行。每单位一夜最多变异两次（含融契），每夜融契最多两次，换节点不会重置。T 增潮仍遵守冷却、次数和容量限制。历史例夜沿用旧变异限制。
- 方向键、A/D、中键拖曳平移；边缘滚动可在设置中开关。暂停时也可操作镜头。地面点击不下达移动命令。
- 战斗中的 P4 手柄指令保持：Start 暂停，摇杆按下切倍速，肩键切换单位，X 打开指令，方向键/A/B 进行选择。右摇杆平移镜头，Back 打开暂停菜单。手柄事件已走到例夜结算，实体手柄待验。

例夜战斗使用正门庭、偏楼上压和两线交潮三组波次，头目在 0/100/210 秒进入正门、梁影和合潮阶段；均为真实波次变化。各场上限由数据配置为 180–360 秒，决策、基地边界、走速和名册胜负规则沿用 G0。P7成长夜香火每秒回复0.24，胜利最多获得12香火、4名分（受60/12上限约束），实际增量写入账本；地图页明确显示数值。历史例夜仍为每秒0.12、胜利8香火。

## 观祭与本机复盘

入夜选择「观祭」，编排全68个单位、合法岗位、正门庭或偏楼上压波次、倒计时、双方香火、名分和 AI 凶度；可选全部十二条科仪。「编排祠场」可选关卡块、头目、无册修饰；选块会更新可用的合法初始岗位。可选开启「今夜构筑」并选择「点册与破门」或「守门与上梁」模板：仅为编制中对应 ID 的首名单位配置表中四槽，默认关闭，不发放全库存。自定义鬼潮替换所选布置的零秒波次，后续波次沿用该布置数据。

选择旁观时双方 AI 执掌；选择「我守香」或「我夺名」时只由另一侧 AI 执掌。AI 经同一套购入、部署、点册、修门、升级、变异和增潮规则付费执行。缓/常/凶只改变决策间隔、概率和偏好；两侧的钱包分别计账，仍是同一种香火。双 AI/对祭用固定守方参考判定并显示实际获胜席，名分归零保留既有守方十秒将熄窗口。

旁观和复盘可暂停、平移镜头、点击完整单位卡或用肩键切换。开启导演后最多三次成功指令：增潮仍扣攻方香火、修门仍扣守方香火并派人实际施工、暂停须在进行中使用；失败指令不耗次数，导演不能关闭失败条件。

结夜选择复盘会带入今夜种子；也可在观祭页输入本机已记录的夜程/观祭种子。选择一场记录进行逐步回放，结束时核验全部成功命令、关键事件和终局战斗状态。夜程完成战斗自动归档；观祭可保存当前片段，终局保存完整记录。归档位于 `user://battle_replays/`，各文件有校验和并绑定 Godot 与战斗规则版本。

种子索引的是本机实际输入记录，单独字符串不包含玩家操作。升级前没有记录的旧夜程不能凭种子还原；旧 P5 存档继续后只能记录继续点起的片段。当前不提供跨电脑同步或 UI 导入，整夜连续播放留给后续。复盘使用 JSON 可读状态及无对象二进制精确数值镜像，避免十进制浮点往返改变冷却边界。相同引擎/规则下核验有效，未声称跨平台位级一致。

## 数据与实现

- `data/nights/example_night.json`：节点、分支、固定科仪、初始班底、资源上限、休整及一次例夜复香规则。
- `data/nights/p5_battle_profiles.json`：各场时间、真实波次、头目阶段和可调门耐久。
- `data/nights/p5_rewards.json`、`p5_events.json`：编制、占位香器、技艺、名帖、变异方、保命牌及两个事件。所有卡显示实际数值；成长夜由 `p7_growth_night.json` 将旧占位属性/构筑牌替换为实际物品、点职和材料。
- `NightRun.gd` 负责合法阶段转换、一次性领取、费用、库存、构筑、种子、存活/陨落和解锁状态；`NightBattleBridge.gd` 将连续一夜接入既有模拟器。
- `BattleSnapshot.gd` 保存实际战局，`NightSave.gd` 使用版本、校验和与临时文件替换。夜程战斗同时记录成功操作和精确时间步，存档继续保留该场记录。`BattleRecord/ReplayArchive/ReplayPlayer` 提供战斗级本地复盘。
- `data/items/censers.json`、`arts.json`、`nameplates.json`：20/16/12 个装备 ID 和参数。I20 可占槽但明确为未完成接口，其他19件香器和全部技艺、名帖有实际效果。`growth_rules.json` 与 `job_stamps.csv` 提供变异、融契、点职与借神规则；F04 暂未实现。
- `src/growth/GrowthEngine.gd` 执行费用、来源、库存、次数、概率和效果；成长快照保存装备、冷却、材料、融契与变异次数、随机状态、灰军身份。活着离册与实际陨落分开记载。
- G0 费用、点册、维修、变异等基线仍在 `data/levels/p4_battle.json`。完整参数与初稿说明见 [数据约定](data/README.md)。

## 调试与验证

夜程内战斗保留 F1 网格、F2 身高、F3 掩体/退守线、F4 镜头框、F6 单位、F9 弹道、F10 FPS；禁用会重置战局的 F5/F7，防止绕过夜程。单独打开 `scenes/combat/Combat.tscn` 仍可使用 P4 独立战局及 F5/F7 调试。

```sh
# P0–P8 无窗口回归，含历史成长夜、全员、存档与跨场身份；证据用 p8-* 前缀
./tools/test.sh

# P7 实际效果、六流派、成长观祭、磁盘复盘与原生截图
./tools/godot.sh tests/P7Suite.tscn -- --capture --event-frames
./tools/godot.sh tests/P7NightSuite.tscn -- --capture
./tools/godot.sh --script tools/p7_ui_smoke.gd

# 原表保真及错误配置启动拦截，只修改临时副本
python3 tests/test_boot_guard.py --godot /absolute/path/to/Godot --report-prefix p8

```

P8 当前结果与原生截图在 `docs/phase-reports/p8-*`；P7历史结果保存在 `p7-*`。六条流派试炼是标明初始接触、环境和受损门的作者验收局，其时间不算普通夜程时长；P7 规则下的普通成长夜已独立完成两席全程通关，守香战斗累计20分、夺名10分33.82秒，单场均为2–6分钟且未使用免费复香。这些历史通关不代表新 P8 技能组合下的整夜平衡验收。完整夜程使用正式决策接口和固定步长推进，不修改生命、门耐久、位置或时钟来取得胜利；特定边界夹具与界面布局夹具会明确标识。无窗口和渲染验收有重叠，不相加当作独立覆盖。

历史阶段：[P0](docs/phase-reports/P0.md)、[P1](docs/phase-reports/P1.md)、[P2](docs/phase-reports/P2.md)、[P3](docs/phase-reports/P3.md)、[P4/G0](docs/phase-reports/P4.md)。Windows 真机与跨平台字体尚未验证，`exports/windows/` 仍是 P0 历史包；当前请运行源码。
