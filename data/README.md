# P0 数据约定

来源：甲方 [GDD v0.2](https://gh393872102.github.io/ye-ci/)，版本日期 2026-11-15，2026-11-17 同步。

- `units/characters.csv`：来自 `tables/夜祠_人物表_v0.2.csv`，32 行，保留全部列名与原始值。
- `units/ghosts.csv`：来自 `tables/夜祠_鬼物表_v0.2.csv`，32 行，保留全部列名与原始值。
- 两张源表不插入注释行，以免破坏原始表头；此文件是对应的来源头说明，采集摘要在 `docs/source-manifest.json`。
- `units/troops.csv`：按开发规范 P0 §4.6 建立 T01–T04。祠役防御、速度等为初稿占位，待甲方或后续阶段校准。全表仍为初稿，未宣称已经完成平衡验收。
- 所有 CSV 是 UTF-8 无 BOM、LF。Godot 导入器设为 `keep`，由运行时代码读取，不误当多语翻译 CSV。
- 单位数值保持源表字符串，以原列名访问。以后构建战斗实体时做类型转换；不得把表中的“速度”直接当成身位/秒。P0 路径估算只用 `Rules.WALK_SPEED_REF=2.2`。
- `Data.get_unit(id)` 返回只读字典，整体缓存亦只读。缺列、重复 ID、无效数值或列数错误均记录，Boot 阻止进入战场。原表没有 `skill_id` 外键，P0 不虚构技能 ID 或技能实现；后续引入外键时须同时加入引用校验。
- `strings/zh_CN.csv` 是 `keys,zh_CN` 本地化表，Data 启动时注册到 TranslationServer。原表姓名、技能等文案仍直接来自原表。
- `levels/reference_gate_court.json` 记录 0–120 身位各分区、10 个掩体岗位、两枚静态占位。P0 不实现寻路，退守调试竖线仅标记预留防线。
- `items/`、`rituals/`、`fusions/`、`mutations/` 的空表只有 `id` 表头，属于后续阶段入口，本阶段不加载且不填未来内容。`levels/chunks/`、`nights/` 同理。

身位、默认镜头、层高等锁定量统一在 `src/autoload/Rules.gd`，不能在其他场景另设缩放。F5 按规范用全图宽度 120 身位估算 54.55 秒，不冒充 P3 实际走路或有障碍防守时间。

## P1 / P2 增量约定

- 上述 P0 条目是历史基线。P1 已在 `levels/reference_gate_court.json` 落实连续楼层、房间、门、楼梯、障碍槽与退守路线；正常 P2 不生成静态占位，P0/P1 回归场景继续使用它们。
- P2 将 CSV 四维转换为战斗实体数值，不修改原表。`units/p2_combat.json` 只补行为类别、基础攻击射程/弹道、技能与特性 ID、出界许可。原表技能/特性名逐字核对；引用未知 ID、未知单位或为默认三人开启出界许可会进入 Data 错误列表，Boot 拒绝启动。
- `skills` / `traits` 中的 `stage` 标出本阶段状态：`channel_interface` 仅为点册位置与读条；`reserved` 只有原文与 ID，没有完整技能效果；`debug_target` 只是压线工具。不能把 H17 普通短符伤害当作封门符，不能把 G01 行走靶当作完成正式拥门/鬼潮行为。
- `levels/p2_defense.json` 定义开场预设、岗位关联的门/障碍和下一退守岗位，复用 P1 空间坐标。本阶段人类到 `post_register` 为止，不执行 P1 预留到后门的完整逃跑语义。
- 伤害公式与 P2 初稿攻击间隔、步行/退守/弹道速度等集中在 Rules / Formula；不根据坐席分叉。
- F5 仍采用 P1 从潮源到名册的 116 身位几何估算（52.73 秒），P0 的全图 120 身位估算函数保留供回归；P3 才进行真实鬼潮路径计时。

## P3 增量约定

- P0–P2 描述保留为历史基线；正常启动已改为 P3 正式潮水。P2 的 `DebugTargetBrain` 和 20 靶上限仅供显式 `tide_enabled=false` 回归场景使用。
- `units/p2_combat.json` 沿用文件名，`phase=P3`：G01/G09/G12 角色为 `tide`，技能和特性均核对原 CSV 名称。G01 拥门每名额外同门攻击者 +8%、最多 +24%；G12 结构伤害倍率 2.5；G09 梁层攻击倍率 1.25、落地 2 秒攻击倍率 0.75，均经共享公式。梁增强条件仅 `floor_id=3`，本关的二楼 `floor_id=2` 不冒领增强。
- `wu_mian` 包含 `fears_light=true`、灯伤害倍率 1.25、超度阻力倍率 0.8，本阶段只是待接灯/超度的数据接口，未宣称已有结算。
- `levels/p3_tide.json` 定义四排纵深偏移 `[-54,-36,-18,0]`（仍在 64 px 可走带）、普通间距 76 px、门前 48 px、容量 150、五波及门障耐久。家具后侧缺口根据排分配不同深度，避免多排合并成同一像素。
- 五波时间为 0/16/32/48/64 模拟秒，总计 72 G01 + 2 G12 + 4 G09 = 78。生成点始终在潮源 x=0，有空槽才生成；调试视觉夹具单独标为 `preset_visual_tide`，不参与路径时间验收。
- CSV 四维不改。普通水平速度映射 `clamp(2.2 + (速度−8)×0.05, 2.0, 2.4)`；故 G01=2.2、G09=2.4。G12 按大形规则采用 1.6，爬梯/绳索系数 0.6。空图强制白衣 2.2。
- P3 耐久覆盖：外门 950、内门 800、殿门 650、名册门 300、二楼廊门/香案门各 450、梁门 300；默认三道障碍各 240。未改 `reference_gate_court.json` 的空间数据及 P1/P2 历史基线，旧/新值和调整原因见 P3 报告。
- 侧墙绳索从地面 87.2 身位连续走到二楼 90 身位；随后走二楼房间，经 110→113.5 身位的既有后楼梯回到地面。只有 G09 选择该路线；普通潮沿地面。`floor_id` 只在换层端点更新。
- `TideCatalog` 在 Boot 前检查关键字段、四排唯一性、可走带、速度范围、门引用、波次顺序/单位和路线范围；错误拒绝启动。
- 首次入房判定使用地面层、身体前缘到达名册房 104 身位边界，计时从预设重置并开始推进起。记录预设、步长、首次单位、位置、破门与换层事件，不能以预放潮或几何估算代替。

## P4 增量约定

- 正常启动现为 P4 开战前选席，P0–P3 描述保留作历史基线。两种坐席共用 P3 开局、单位、路线、耐久、伤害公式；P2/P3 测试显式关闭决策会话保持历史基线。
- `levels/p4_battle.json` 是当前决策与胜负数值的唯一配置入口。`BattleCatalog` 在 Boot 前检查必需字段、数值范围、单位引用、占位装备 ID、点册与将熄时间；负费用和未知单位会阻止进入战场。
- 开局香火守香 20、夺名 16；名分 8；香火每模拟秒恢复 0.12，上限 60。购入的预留款也计入资源上限，右键取消只退一次，不会借回复/退款超额制造资源。
- 购入 T01/T02/T04 费用 5/8/6，H01/H09/H17 为 12/12/10。活跃具名上限 8、杂兵上限 4、岗位上限 3；同一具名 ID 只允许一名。部署复查岗位、职分、人数及身份，不重复扣款；非法地点保留预留订单供取消或另选。
- 升级 8 香火增加最大/当前生命各 15、防御 2，最多三级；`ritual_incense` 是一件明确标注的占位香器，6 香火增加生命 10、防御 1，占一槽。完整装备表仍为空接口，留给 P7。
- 晚的点册在正式 P4 改为玩家付费触发：4 香火、4 秒、成功回报 3 香火与 1 名分并净化目标；不再自动免费施放。范围 8 身位、同层、安全室内施术，头部视线可越过桌案但门墙仍阻挡。受伤、移动、目标死亡或离开范围打断，不退款；P2 无会话回归保留原读条接口。
- 修门 6 香火、回复 300 耐久，维修者实际走到门内侧 40 px 后工作 3 秒并返回岗位；允许恢复毁门。路径不存在、满耐久或重复维修均拒绝。本参数是 P4 初稿，不改 P3 门障初值。
- 上梁 G09 / 破门 G12 花费 12/15，每个 G01 只可变异一次，原地保留当前生命比例并切换真实战斗配置。上梁只接受尚未越过地面侧墙绳索入口的白衣，不倒走或瞬移补路线。提灯返回明确未实现原因，融契仅 UI 入口，不进行结算。
- 增潮花费 10，向同一个潮源队列添加 8 个 G01，冷却 30 模拟秒、每场上限 3；仍受 P3 总容量 150 约束。
- 战局上限 240 秒；名册房有鬼且无存活防守者时累计占领 12 秒，期间每秒抽取 0.25 名分；任意防守者返回则占领以 2 倍速度回退。名分归零后守香有 10 秒将熄窗口，恢复名分则重置；夺名归零立即胜利。最终原因与首次破门分别保存。
- `strings/p4_zh_CN.csv` 为新增 UTF-8 无 BOM / LF 本地化表；六张立绘使用独立 SVG 占位，不改源 CSV 的姓名、四维、技能原文。`units/p2_combat.json` 仅补更卒 T04 的战斗配置，完整技能仍以各自阶段状态为准。

## P5 增量约定

- P0–P4 条目保留为历史基线；正常 Boot 改进 `Night.tscn`。`nights/example_night.json` 定义 11 个图节点，每条路线实际走 10 节，其中 `n06` 休整与 `n06r` 风险战二选一；三选一是战后阶段，不重复计为地图节点。
- 科仪固定 `example_incense`。凶夜未开放，未知 kind/科仪会被拒绝，不用背景或名字冒充规则。
- 初始班底是守香 H01/H09/H17/T01/T02、夺名 16 个 G01。每次战斗只部署现有存活编制，保留生命、升级、装备、变异和初始岗位；上一场实际退守不自动把下一场的初始岗位永久后移。因战中退守后补购而导致原岗位超过3人时，下一场按距离选择同职分的合法空余掩体，并记录 `night_redeploy`，不超过岗位部署上限。已排队但尚未生成的鬼仍属于编制。
- 两种资源仍为香火/名分。夜内上限 60/12，胜利奖最多 +8/+4，实际增量受上限约束并记录；普通休整回复存活者 25% 最大生命、4 香火和1名分，不复活。教学一次免费复香恢复当前战斗开局名单及当时资源，生命至少50%、香火至少16、名分至少4；这是明确展示的一次失败重试。
- `p5_battle_profiles.json` 只改变本节点实际波次、时限与可选门耐久；门压、上楼、交潮具有不同组成和时间。头目 0/100/210 秒三段，分别加入 G12、G09 和混合潮，原 CSV、空间坐标、走速、伤害公式和胜负判定保持。
- 夜内构筑直接修正既有会话规则：香火回复每层 +0.06/秒至 +0.18；点册时间每层 -0.5 秒、最多 -1 秒且不低于3秒；点册成功香火每层 +1 至 +2；维修回复每层 +100 至 +300；变异费用每层 -2 至 -6 且不低于1；增潮数量每层 +2 至 +4。装备/属性牌直接记入相应单位，进下一场不会重复叠加。
- `p5_rewards.json` 使用权重抽取互异的三张牌，保证可用构筑，保命类始终有机会、同组三张最多一张保命。各牌显示作用/数值/目标；库存与三选一内容随存档保留，不因读取重抽。普通白衣无装备槽，精英才可作为鬼方香器/名帖目标。上梁/破门变异方奖励可选择白衣直接兑现一次变异，保留身份及损伤比例；夜市仅支付卡面12/15香火，战后选择不另扣费，避免满编且构筑封顶时奖励不足三张。
- 图鉴解锁接口仅保存遭遇/招募 ID，不授予永久属性。完整图鉴界面留给 P9。保存和恢复位于 NightRun/NightSave/BattleSnapshot：JSON 可读、版本化、校验和、原子临时文件替换；包含战局对象引用、点册、维修、弹道、队列、资源、RNG、库存与种子。
- 配置数值是 P5 教学初稿。完整 P7 装备表及三条流派强度、正式凶夜 25–40 分钟时长仍需后续阶段验证。


## P6 增量约定

- Boot 仍进入入夜，新增观祭入口。`modes/p6_modes.json` 外置已实现单位、两种波次布置、初始编制/资源、120–600秒时限、容量、三档 AI 决策偏好和三次导演上限。`ModeCatalog` 禁止用属性倍率设置凶度，未知单位/科仪/非法岗位会阻止启动。
- 自定义编制只替换布置的零秒波次，后续波次仍来自 P5 数据；不增加第二张几何地图或另一个公式。人类具名唯一、合法岗位与职分、每岗3人、杂兵4人/总12人及初始鬼潮120上限在场景变更前校验。
- 守香和夺名例夜保留 P5 单席判定。观祭双席以守方世界状态为统一参考，独立香火钱包都自然回复，点册异步奖励固定归守方；名分耗尽保留十秒将熄窗口，名册占领/司线断等既有条件给出 `winner`。每个夜程战斗节点显式给出两席主副目标。
- `SeatBrain` 各自持有以种子和坐席初始化的 RNG；缓/常/凶间隔8/4/1.75秒并有有界抖动，费用、CD、唯一性和容量完全交由 `BattleSession.execute_for()` 的原决策方法校验。禁止把模型输出作为金额或胜负裁决；本实现没有外部 AI 服务。
- `BattleRecord` 保存初始战局、成功玩家/AI/导演命令、精确时间步和终局事件。JSON 保留可读字段；`initial_exact`/`steps_exact` 用 `var_to_bytes` 的基础值编码保留 double 原位数值，读取使用不允许对象的 `bytes_to_var`，并与可读镜像一致校验。先验证版本、规则摘要、结构、动作白名单、导演次数、参数及初始快照，再变更场景。
- `ReplayArchive` 以安全哈希文件名索引本机种子，记录同一夜每个已结束战斗。存档携带本场记录；旧 P5 存档无历史指令时标为继续片段。整夜连续回放尚未实现，保留 seed/node_id/source/mode 逐场接口。
- 回放兼容摘要包含原 CSV、战斗配置、地图、Rules、公式、模拟器、Session、潮水、移动/技能/实体与快照脚本。录像记录了决策结果，因此播放不重新抽 AI；摄像机、UI选择、暂停等待的墙钟时长和纯视觉信息不参与战斗一致性判定。


## P7 增量约定

- 资源初稿在完整夜程失败后按GDD6.4/15.4调曲线：仅成长夜自然回复经0.12→0.18→0.24香火/秒、每场胜利香火由8→12。`p7_growth_night.json`是唯一入口，两席使用同值；开夜20/16、资源上限、名分奖、源CSV、费用、走速与波次不变。历史例夜保留0.12/8。此项是当前夜程的固定资源规则，不是额外成长层；地图会公开说明。

- 成长夜使用 `nights/p7_growth_night.json`，与历史 P5/P6 例夜通过 `new_growth_run()` 分开入口。其奖励池移除旧 `equipment/stats/build/mutate` 原型牌，替换为真实装备、点职凭据、残名和新增编制；保命牌仍在，源 CSV、路径与波次没有改写。
- 装备唯一来源为 `items/censers.json`（I01–I20）、`arts.json`（Y01–Y16）、`nameplates.json`（N01–N12）。四槽为1香器+2技艺+1名帖。普通白衣无槽；库存按真实物品消耗/退回，暂停时可装卸，物品的次数和冷却不因装卸而清零。I20为明确标出的可装备接口，没有伪造效果。
- `items/growth_rules.json` 定义 V01/V02/V03 的8/12/15费用、源单位与结果；V04融契20香火。一个单位一夜最多两次变异（融契计一次），每夜融契最多两次；F01/F02/F03/F05已接规则，F04为interface。入水/披衣/错名仅锁定接口。残名是道具材料，不进入HUD资源栏。
- J01/H09 增加机关标签并将维修费用乘0.8；J02/H17在符被打破时给2身位友军3秒防御×1.2。点职不换模型。借神12香火+1名分，必须在香案或名册读条；普通失败率15%，游神旗标35%，成功为短时援手，失败为G30敌方与可读反噬。收编和无册触及夺回走真实阵营变化。
- `GrowthEngine` 保存一夜库存、随机数状态、融契次数、发现记录与每单位四槽、变异次数、技能冷却/次数。`NightBattleBridge` 对可变记录深拷贝，灰军以稳定night_uid携带，重绑问灯来源，跨战清除未完成冲锋；同场快照保留冲锋。活着转敌或融契消耗记为离册，不伪称陨落。
- `modes/p7_growth_templates.json` 为可选观祭模板，配置在Boot校验。只给当前编制匹配的首名单位装备列明物品；默认关闭。旁观、对祭、夜程和试炼共享GrowthEngine与战斗实例。
- `nights/accept_*.json` 是六条可重复流派验收局，所有预置接触位置、危门耐久、锁点、水面及科仪旗标明确写入文件。破门潮和上梁奇袭从实际潮源出发；预置接触场景不作为普通夜程的时间/难度证据。

## P8 增量约定

- 原 `characters.csv`、`ghosts.csv`、`troops.csv` 仍为姓名、职分、基础四维、技能名/费用/描述、特性及标签来源。`p8_humans.json`、`p8_ghosts.json` 增加 68 个可执行行为映射与参数；`RosterCatalog` 在启动时检查每个脚本资源及真实方法，不以一个未实现字符串占位通过校验。
- `Session.configure_roster()` 启用 P8 专属行为，复用同一 Simulation、Formula、Brain 和 GrowthEngine。历史 P0–P7 显式场景保持历史规则；入夜的成长夜通过 `new_roster_run()` 启用 P8，观祭 UI 默认启用完整编制。费用/次数/冷却由实际 handler 执行，外部 `unit_skill` 不能传 `copy_id` 冒用其他技能。
- `p8_appearance.json` 定义规范 8+8 套骨架、独立头面、持物与色板。普通单位 80 世界像素，大形 G17–G24/G31/G32 为128–176；P8由RosterEngine应用该表身高，不重写历史阶段配置。画像全部位于面板，T01–T04无具名立绘。最终精绘与高规格占位分别记数，来源见 `assets/portraits/p8/manifest.json`。
- `may_briefly_leave_base` 仅 H25/H31 为真。H31须已标记精英，直线打击、外门/院心合计最多3秒，返回合法岗位、不追第二目标；H25仅门扇施工。H15飞瓦沿基地内合法路线换岗位，不开启外出权限。`p8_routes.json` 单独定义G07窄窗和G24机关侧路，均逐段移动，不放大地图。
