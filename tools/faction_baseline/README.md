# 《夜祠》单阵营战斗基线

本实验用正式 Combat.tscn 和双席胜负裁决，比较初始编制分别来自一司与一谱的战斗。每行依次与无名潮、习俗厉、大形、无册谱交战。每局都让引擎自然结算。JSON 逐局给出守军与岗位、没有合法岗位或不在购买表中的角色、攻方名单、赢家、原因、模拟秒数及结算时存活数。

## 本轮实跑（同一种子，80 个测试条件）

表内数字为守方在四个不同对手中获胜的局数。每行有 16 场。

| 条件 | 守香司 | 武卫司 | 符法司 | 奇人司 | 合计 |
|---|---:|---:|---:|---:|---:|
| 旧目标，八鬼 | 0 | 0 | 0 | 0 | 0/16 |
| 旧目标，同数 | 1 | 3 | 0 | 0 | 4/16 |
| 守册，八鬼 | 0 | 0 | 0 | 0 | 0/16 |
| 守册，同数 | 1 | 3 | 0 | 1 | 5/16 |
| 守册，同数，优先册房 | 1 | 3 | 1 | 2 | 7/16 |

奇人司三名合法守军在默认目标下四战均于 16.05 秒判负，三人仍在场且名分仍为 8。保持同数、同种子和首岗，指定守册后，对无名潮守到天亮，对另三谱在 133.067 至 224.233 秒间因占领或熄册落败。符法司同数对无名潮按首岗布置时在 222.267 秒被占；仅把初始部署移向册房和厅门后守满 240 秒。该组为六人对六鬼，各人均无初始装备，符法司自带借鬼技能可能发生临时转化。下一轮应区分纯编制胜利与全程不借兵的胜利。

## 复跑方法

在已导入的 Godot 4.7.2 工程根目录执行以下命令。每个进程负责一个守方和四场对战，重新生成对应的四场记录。完整矩阵覆盖守香司（0）、武卫司（1）、符法司（2）、奇人司（3）。

```sh
for seat in 0 1 2 3; do
  godot --headless --script tools/faction_baseline/Matchup.gd -- "$seat"
  for mode in equal hold equal-hold equal-rear-hold; do
    godot --headless --script tools/faction_baseline/Matchup.gd -- "$seat" "$mode"
  done
done
```

| 文件前缀 | 招入的鬼 | 防守目标 |
|---|---|---|
| row | 同一谱的八种鬼各一 | 默认旧规则 |
| equal | 总数与当局守军相同 | 默认旧规则 |
| hold | 同一谱的八种鬼各一 | 指定守册目标，存活的本方具名守军能继续驻防 |
| equal-hold | 总数与当局守军相同 | 同上 |
| equal-rear-hold | 与 equal-hold 相同 | 同上，唯一额外改动是优先合法册房岗，其次厅门与内门 |

**控制条件。** 同一随机种子 YECI-FACTION-BASELINE-01，默认 G0 地图、完整门与土垒、默认 240 秒、每步 1/60 秒。开局守 20、攻 16 香火、8 名分，开启成长及完整角色技能。测试直接编制初始人员、不收招募费；遍历守方源表，将符合当前购买表和岗位限制的单位部署在第一个合法岗。受真实可购买名单限制，守方四司依次有 3、2、6、3 人入场。进攻侧按源表放入四条路线，从起点进场；同人数对照从八个角色按等距索引抽取，具体名单见 JSON。未安排新波、外部指挥、主动买卖、换装、变异或付费增援。角色会自主移动、施术与攻击，借鬼或错录在战斗中可能改变归属。

**读数范围。** 各四场共享种子，改变的是对手，不能作为四个独立玩家样本。初始编制纯度与“全程禁止阵营能力带来的临时转化”是不同指标。守军先选合法岗而非熟手布防，攻方无需逐个解锁。等人数也没有控制总造价、技能组合、出生线及射程。科技、肉鸽掉落、养成、真人操作以及大型场景渲染帧率均不在此实验内。一边获胜只能作存在性证据；判断普通玩家是否容易单阵营通关需要正式夜程、混合地图与多种子的人机/真人分层样本。

**本轮复审。** 首次交叉对战揭露三项脚本错误：临时改派为守方的 G07/G09 读取了只属于进攻 AI 的上梁状态，改派为攻方的祭职人物绘制了只属于防守 AI 的读条，鬼方技能对门或土垒错误读取人物死亡字段。修正这三个分支后重新生成记录。若运行出现 SCRIPT ERROR，须先修复并重跑相应行，再用于平衡判断。

## 普通开局与凶夜招募岗位

在工程根目录执行 `godot --headless --script tools/faction_baseline/NightRecruitPosts.gd -- /tmp/ye-night-recruit-posts.json`。程序在四个普通例夜种子分别购买四司各一人，并在四个凶夜招募夹具中注入源表卡，再经实际付款、地图生成和部署检查。输出包含阵营、角色、剩余资源或实付、地图和岗位。普通场记录开局的混编阵容，凶夜不计算卡片自然出现频率，两者都没有胜率分母。

`night-recruits-before.json` 是修复前的四次普通开局查询与四次受控集市观测，`night-recruits-after.json` 将普通部分扩展为四种子乘四名实际购买者，并保留同一组凶夜对照。普通复跑省略可选的旧快照迁移项。若要单独复核迁移，在旧版本用同一脚本和种子设置 `YE_WRITE_PRIOR=1`，随后在新版设置 `YE_READ_PRIOR=1`；两个进程顺序运行，共享临时文件 `/tmp/ye-prior-recruit.snap`。
